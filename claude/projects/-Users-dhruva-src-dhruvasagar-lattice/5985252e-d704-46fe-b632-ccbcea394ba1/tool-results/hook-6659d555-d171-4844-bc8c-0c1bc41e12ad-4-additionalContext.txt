**#S308** Systematic bugfix: Replace scattered is_active checks with unified render_active flag to fix visual artifacts when popup overlays are focused in Lattice GPUI text editor (May 24 at 8:39 AM)

**Investigated**: Examined line 984 in window.rs (one of two remaining `is_active` usages found by grep). This was a field assignment to the `EditorElement` struct within the `paint_pane` function. The field controls whether the element paints cursorline background decorations.

**Learned**: The `is_active` field on `EditorElement` is the final control point for cursorline background rendering. By passing `render_active` (which is `is_active && !popup_owns_active`) instead of raw `is_active`, the document pane's cursorline disappears when a popup has focus, completing the inactive appearance. This is edit #8 in a systematic refactor that has now touched: cursor position/shape, scroll position, visual decorations (selection/search/substitute), status bar colors, syntax highlighting visibility, and cursorline background.

**Completed**: Applied edit #8 on line 984: changed `is_active,` to `is_active: render_active,` in the EditorElement field initialization. Ran `cargo check -p lattice-ui-gpui --features window` and confirmed clean compilation with no errors. The `render_active` flag now flows through all rendering decisions that should suppress when a popup owns focus.
